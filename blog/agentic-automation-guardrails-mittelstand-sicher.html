Automatisierung mit klaren Leitplanken

Freigaben, Rollen, Protokolle und Rückfallwege für kontrollierte Agenten.

Text & Einordnung: Patrick VachTechnische Angaben sind zeitabhängig und werden vor Projektentscheidungen neu geprüft.

Was sind Guardrails?

Guardrails = Regeln die verhindern dass KI etwas Falsches tut.

Analogie: Fahrassistent

  • Ohne Guardrails: Auto fährt autonom, keine Limits
  • Mit Guardrails: Auto fährt autonom, aber bleibt in Spur, hält Geschwindigkeitslimit, stoppt bei Gefahr

Die 7 wichtigsten Guardrails

1. Human-in-the-Loop

Kritische Entscheidungen brauchen menschliche Freigabe.

Beispiel: Agent darf Rechnungen <1.000€ automatisch buchen, >1.000€ brauchen Approval.

2. Confidence Thresholds

KI gibt Sicherheit an: >90% = Auto, 70-90% = Review, <70% = Manuelle Bearbeitung

3. Action Whitelisting

Agent darf nur vordefinierte Actions ausführen.

Erlaubt: E-Mail senden, Datenbank-Read
Verboten: Daten löschen, Geld überweisen

4. Rate Limiting

Max. 100 API-Calls/Minute verhindert Kosten-Explosion.

5. Timeout Limits

Agent darf max. 5 Minuten laufen verhindert Endlos-Loops.

6. Audit Logging

Jede Action wird protokolliert: Wer, Was, Wann, Warum.

7. Rollback Capability

Agent-Fehler müssen rückgängig machbar sein.

Mehr zu Agents: Agentic KI im Mittelstand: Von der Theorie zur Praxis

Guardrail-Level nach Risk

Risk Level Guardrails Beispiel
Low Risk Logging, Timeout E-Mail-Klassifikation
Medium Risk + Confidence Threshold Kundenservice Antworten
High Risk + Human-in-Loop Rechnungen buchen
Critical Risk + Approval Workflow Verträge unterschreiben

Human-in-the-Loop: 3 Patterns

Pattern 1: Full Human Review

KI schlägt vor, Mensch entscheidet immer.

Anwendungsfall: Strateg ische Entscheidungen, HR, Legal

Pattern 2: Conditional Human Review

KI entscheidet bei einfachen Fällen selbst, eskaliert komplexe.

Anwendungsfall: Kundenservice (80% auto, 20% escalated)

Pattern 3: Post-Facto Review

KI handelt selbstständig, Mensch prüft nachträglich (Stichproben).

Anwendungsfall: Rechnungsverarbeitung (5% Random Sampling)

Confidence Thresholds in der Praxis

Beispiel: Dokumentenklassifikation

  • >95% Confidence: Automatisch klassifizieren
  • 85-95%: Klassifizieren + Flag für Review
  • 70-85%: Vorschlag an Mensch
  • <70%: "Nicht sicher" manuelle Klassifikation

Code-Beispiel:

confidence = agent.classify(document)
if confidence > 0.95:
    auto_process()
elif confidence > 0.85:
    auto_process() + flag_for_review()
elif confidence > 0.70:
    send_to_human(with_suggestion=True)
else:
    send_to_human(no_suggestion=True)

Action Whitelisting

Agent darf nur explizit erlaubte Actions ausführen.

Whitelist-Beispiel:

  • send_email(to, subject, body)
  • create_ticket(title, description)
  • read_database(table, filter)
  • delete_database(table)
  • transfer_money(amount, to)
  • execute_code(script)

Implementation: Agent-Framework prüft ob Action in Whitelist. Wenn nein Error + Log.

Audit Logging: Was muss geloggt werden?

Minimum Logging:

  • Timestamp: Wann wurde Action ausgeführt?
  • Agent ID: Welcher Agent?
  • Action: Was wurde gemacht?
  • Input: Welche Daten wurden verarbeitet?
  • Output: Was war das Ergebnis?
  • Confidence: Wie sicher war die KI?
  • User (if any): Wer hat freigegeben?

Retention:

DSGVO: Logs müssen nach X Monaten gelöscht werden (abhängig von Anwendungsfall).

Mehr zu Compliance: EU KI Act: Was Unternehmen jetzt wissen müssen

Rollback: Fehler rückgängig machen

3 Rollback-Strategien:

1. Database Transactions

Alle DB-Changes in Transaction bei Fehler: Rollback.

2. Snapshots

Vor kritischer Action: Snapshot. Bei Fehler: Restore.

3. Compensation Actions

Jede Action hat "Undo"-Action. Email gesendet Recall Email. Rechnung gebucht Storno-Buchung.

Beispielhafte Case: E-Commerce mit Guardrails

Online-Shop nutzt Agent für Kundenservice.

Guardrails implementiert:

  • Confidence Threshold: >85% auto, <85% escalation
  • Action Whitelist: Darf Gutscheine bis 50€ vergeben, keine Retouren ohne Approval
  • Rate Limit: Max 10 Gutscheine/Stunde
  • Human Review: 10% Random Sampling
  • Logging: Alle Aktionen für 12 Monate

Ergebnis nach 3 Monaten:

  • 75% der Anfragen komplett automatisch
  • 25% escalated zu Mensch
  • Fehlerrate: 0.8% (8 von 1000)
  • Alle Fehler durch Human Review erkannt korrigiert

Tools für Guardrails

1. Guardrails KI (Open Source)

Framework speziell für LLM Guardrails. Output-Validation, Input-Sanitization.

2. LangChain Callbacks

Hooks für Logging, Monitoring, Custom Rules.

3. Custom Middleware

Eigener Layer zwischen Agent und Actions. Prüft jede Action vor Ausführung.

Die 5 häufigsten Fehler bei Guardrails

1. Zu wenig Guardrails

"YOLO-Deployment" Agent macht was er will Chaos.

2. Zu viele Guardrails

Agent braucht für alles Approval kein Effizienzgewinn.

3. Falsche Thresholds

Confidence >50% = Auto zu viele Fehler. >99% = Auto kaum Automation.

4. Logging vergessen

Fehler passiert keine Ahnung was schief ging.

5. Kein Testing

Guardrails werden nicht getestet funktionieren nicht wenn nötig.
